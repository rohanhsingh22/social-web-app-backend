# Taste
- Prefers pragmatic, temporary workarounds (e.g., a feature-flagged dev login) to unblock development when an external dependency is unavailable, deferring the full integration until it is ready. Confidence: 0.7
- Tends to ask for a suggestion/plan, an explanation/diagnosis of an error, or a status/overview of current capabilities before implementation proceeds rather than requesting immediate action. Confidence: 0.85
- Prefers the assistant to draft ready-to-send written messages for others — teammate/agent handoffs, PR descriptions, commit messages, or suggestion messages to accompany a change — rather than just explaining an idea conversationally. Confidence: 0.8
- Wants temporary workarounds and changes-that-need-reverting tracked in a dedicated doc (e.g., `doc/temporary-changes.md`) so they can be cleaned up before launch. Confidence: 0.9
- Prefers a written progress/status document that summarizes what has been built so far and how a user can access it (startup commands, endpoints, socket events, dev-login flow), distinct from setup docs and specs. Confidence: 0.85
- Wants the assistant to proactively test already-implemented features and hunt for bugs (including deep root-cause tracing) before moving on to new work. Confidence: 0.7
- Likes checkpoint reviews after a body of work that produce a prioritized list of remaining items (bugs/risks, unfinished features, hardening and testing gaps) rather than jumping straight into the next implementation. Confidence: 0.8
- Wants features made production-ready, not just functionally working — values robustness, graceful degradation, accurate error messaging, and defensive hardening (presence TTL/heartbeats, Redis-less boot, rate limits) before declaring a phase done. Confidence: 0.8
- On the frontend, prefers to avoid repeated API calls by centralizing data access — using React Context for identity/session state and TanStack Query's cache for profile/server data rather than fetching per-component. Confidence: 0.75
- Wants the assistant to have read-only access to the frontend (full codebase) — and to not modify it — even when frontend edits aren't being requested, so it has full-stack context rather than a backend-only workspace. Confidence: 0.85
- Prefers comprehensive error logging throughout the backend — every error should produce a log line, silent catches (empty `catch {}`, `.catch(() => null)`, health checks returning `false`) should be replaced with real error/stack logging, and a global exception filter should surface errors that NestJS's default handler would otherwise swallow. Confidence: 0.85
- Prefers minimal, non-invasive code changes — when multiple fix options exist, favors the one that has the least impact on the existing codebase (e.g., extracting an existing error code into an event payload rather than restructuring auth flow or adding new server-side logic). Explicitly says "keep the implementation minimal" and "do not refactor unrelated code" even when a larger refactor might seem natural. Confidence: 0.8
- When building a new feature/module, prefers to mirror the structure and conventions of an existing similar feature rather than inventing a new pattern (e.g., "just like profile"). Confidence: 0.65
- Prefers to minimize database round trips — proactively identifies and eliminates redundant DB operations (e.g., collapsing a create+update+include into a single create by pre-computing values in application code). Confidence: 0.85
- Prefers to pass already-known data to functions rather than re-querying the database — when data is already loaded in memory, it should be passed as a parameter instead of fetching it again (e.g., passing `Pick<User, 'status' | 'role'>` instead of including the user relation). Confidence: 0.8
- Wants explicit, enumerated verification steps after code changes — provides a numbered checklist of what to validate (typecheck, tests, specific behaviors to confirm) rather than leaving verification approach ambiguous. Confidence: 0.75
- Wants inspection before modification — before changing code, the assistant should read and verify the current implementation matches expectations; if it differs, stop and explain the discrepancy rather than making an unrelated change. Confidence: 0.8
- Wants detailed change reports — after making changes, expects a summary of exactly which files were changed and why, plus the validation commands run and their results. Confidence: 0.8
- Prefers to avoid unnecessary abstractions when optimizing — explicitly rejects adding transactions, caching layers, or other infrastructure for a simple optimization; wants the simplest possible solution that achieves the goal. Confidence: 0.75
- Drives backend work from a phase/spec document (`doc/project-context.md`, `doc/backend-chat-app.txt`) and expects the assistant to check the doc to determine which phases are complete, then complete the remaining phases per the doc rather than deciding scope on its own. Confidence: 0.8
- Prefers lean/minimal seed data and configurations — only keeps content that's needed for the current phase ("for now"), and proactively removes speculative or unused entries (e.g., extra chatroom channels) to maintain focus rather than accumulating options. Confidence: 0.8
- Works on Windows: expects Windows drive paths (e.g., `E:\backend`); shell commands observed use cmd.exe syntax (e.g., `del`) and `npx`/`npm` directly rather than `npx.cmd`/`npm.cmd`. Confidence: 0.75
- Prefers `upsert` over `create` for database writes to ensure idempotency — operations can be safely re-run without producing duplicate records. Confidence: 0.75
- Uses a dedicated `scratchpad/` directory for throwaway scripts — writes temporary TypeScript scripts there, executes them via `npx ts-node`, and deletes them afterward with `del`. Confidence: 0.8
- Always disconnects Prisma Client in a `.finally()` block — consistently uses `await prisma.$disconnect()` inside `.finally(async () => { ... })` to ensure DB connections are properly closed even on errors. Confidence: 0.8
- Uses TypeScript `as const` assertions on array literals of constant data to preserve literal types. Confidence: 0.65
